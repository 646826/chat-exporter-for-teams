# Chat Exporter for Microsoft Teams 0.2.2

## Fixes

- Ordinary website and HTML game-page links stay in the transcript and links.csv instead of becoming failed attachment downloads. Generic role=document containers no longer imply a file card; explicit file cards, media, download attributes and file URLs remain candidates.
- Retry temporary network failures and HTTP 408/429/500/502/503/504 with a bounded delay, respecting Retry-After within the request deadline. Permanent access-denied and missing-file responses are not blindly retried on the same URL.
- Cancel stalled response streams when their deadline expires. Temporary blob/data media now use a bounded worker pool and enforce file/cache size limits during capture instead of launching every fetch at once.
- Prefer actual URL filenames over generic Link labels.
- Show downloaded, failed and skipped counts, and explicitly label an archive with missing files. CSV diagnostics include error codes and request attempts.
- Run the real Chromium DOM/Trusted Types fixtures on macOS as well as Linux CI using a separate temporary browser profile.
- An explicitly requested Store publication now fails visibly when Store authorization is missing, instead of returning a misleading green workflow.

## Scope and remaining work

This is a bounded reliability release, not completion of every requirement in issue #8. The proposed SharePoint viewer-to-file route change was blocked by the execution tool and was not applied. A tracked TODO records that gap. The privileged Microsoft-host transport is also not included: permissions and the existing execution-world model are unchanged. Files blocked by CORS, authentication, Microsoft 365 policy, deletion or expired links can still fail and are reported honestly.

The reported real conversation ZIP was not inspected or re-exported; validation uses synthetic data. No real messages, private tenant URLs or credentials are included in tests or this repository.

Version 0.2.2 is aligned across manifest, npm metadata and bundle identity. There are no new permissions, dependencies or breaking JSON schema changes. Size limits constrain accepted attachments, not total browser-process memory.

## Store delivery

The repository and chrome-web-store environment had no configured Store credential names at the release preflight. A verified build artifact is not a Store upload. Upload, review submission and public publication must be reported separately from CI success. Normal publication keeps skipReview=false and blockOnWarnings=true.
